## Zlecenie i wynik

Zgłoszenie: „napraw mapę, która po ostatnim PR przestała w ogóle się rysować”.
Naprawione, zweryfikowane w przeglądarce, opisane w `docs/PROJECT_HISTORY.md`
(sekcja M5) i w opisie PR #4.

**Root cause:** kolizja nazwy klasy. `app/map.js` nadawał grupie świata
`class: 'warstwa'`, a `.warstwa { … display: none }` w `app/styles.css` to
pełnoekranowa nakładka UI (ADR 0010), domyślnie ukryta — cała zawartość mapy
dziedziczyła `display: none`. W drzewie było 241 ścieżek krajów i poprawny
`getBBox()` (0, 0, 3600, 1800), a `getBoundingClientRect()` = 0, 0, 0, 0.

## Jak zweryfikować wizualnie w sandboxie (nowa umiejętność)

Swobodny egress jest zablokowany (L3), więc `npx puppeteer browsers install`
kończy się błędem pobierania. Działa droga przez rejestr npm — szczegóły
w `docs/setup/ENVIRONMENT.md` §4, skrót:

```bash
cd /home/user/.narzedzia && npm i puppeteer @sparticuz/chromium pngjs
node -e "…brotliDecompressSync('node_modules/@sparticuz/chromium/bin/chromium.br')…"
# biblioteki współdzielone z bin/al2023.tar.br, potem:
CHROME_PATH=…/chromium LD_LIBRARY_PATH=…/libs/lib node skrypt.mjs
```

Mierz w przeglądarce trzy rzeczy naraz — `getBoundingClientRect`,
`getComputedStyle().display` i `elementFromPoint(środek)`; ich rozjazd
wskazuje warstwę, na której zgasła treść (tu: kaskada CSS, nie geometria).

## Pułapki tej sesji

- Zielone `npm test` nie znaczy „aplikacja działa”, gdy testy idą na atrapie
  DOM: atrapa nie liczy kaskady CSS (L13). Kontrakt arkusz ↔ klasy renderu
  mapy jest teraz częścią bramy.
- `gh pr list --head <gałąź>` nic nie zwróci przed pierwszym wypchnięciem —
  najpierw commit i push, potem `gh pr create` (ADR 0004 pkt 1).
- W headless Chromium domyślny jest motyw **jasny** (`prefers-color-scheme`),
  nie ciemny — przy pomiarach kolorów mapy trzeba przełączyć motyw albo
  wziąć to pod uwagę.
